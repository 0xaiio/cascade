# 014 · 「完成后通知」是一个谁都没实现的开关

- 状态：已修复
- 提交：`fix(notifications): 让「完成后通知」真的会提醒（提示音 + 右下角浮层，方式可选）`
- 影响面：**每一个**用户。开关就在下载选项面板里（`DownloadOptionsPanel.tsx:135`），
  字段在 `schemas.py` 里，但前后端都没有任何一行代码消费它 —— 勾了不会有任何事发生。
- 严重度：中。不报错、不损坏数据，但它是「界面承诺了、实现没跟上」的教科书案例：
  一个不生效的开关**比没有开关更糟**，用户会以为是通知功能坏了，然后去查浏览器权限、系统通知中心。

## 问题

下载选项面板第四个开关「完成后通知」（铃铛图标）勾上之后提交任务，任务跑完时：

- 没有任何声音；
- 没有任何弹窗；
- 没有任何日志 —— 因为**根本没有一个地方会去看这个字段**。

这不是「提醒发不出去」，而是「提醒这一步从来没有被写过」。依据：

- 后端：在 `backend/app` 下检索 `notify`，**只命中 `schemas.py` 的字段定义一处**，
  没有路由、没有服务、没有事件消费它（2026-10-18 复核，与 `ai/plan/brainstorming.md` H-01 一致）。
- 前端：`frontend/src` 下检索 `notify_on_complete`，只有 `App.tsx:69`（初始值 `false`）、
  `types.ts:56`（类型）与 `DownloadOptionsPanel.tsx:135`（开关）三处，没有触发点。
- 文档已经承认了这一点：`docs/api.md` 原话是「请求模型接受该字段，但当前下载链路不消费它；
  不要据此期望系统通知」，`docs/design.md` 把它列进「已知限制与设计债」第 6 条。

即：**代码里有一个开关、文档里有一句免责声明，中间什么都没有。**

## 原因

三层都没有实现，缺的不是某一行，而是整条链路：

1. **没有地方决定「怎么提醒」**。`notify_on_complete` 只是 `bool`，
   就算有人想实现，也没有地方让用户选「声音还是弹窗」。
2. **没有地方判定「跑完了」**。`App.tsx` 收到 SSE 后只是重拉 `/api/jobs` 并整体替换
   （`setJobs`），没有比对前后状态；要区分「刚刚跑完」和「一进来就已经跑完了」必须比对
   —— 不比对就会把历史任务反复播报。
3. **读模型拿不到那个开关**。`JobRead` 不暴露 `options`，而 `notify_on_complete` 只活在
   `Job.options_json` 里。前端因此只剩「本次会话里我提交过哪些任务」这一份记忆，
   刷新一次页面，同一个任务跑到终态就不会再提醒。

第 3 条决定了这次必须改后端契约：它不是「前端自己记住就行」的小事。

## 修复方案

### 1. 提醒方式变成全局设置，逐任务开关决定「要不要」

分工刻意做成两层，因为它们本来就是两件事：

| 层 | 字段 | 位置 | 管什么 |
| --- | --- | --- | --- |
| 全局 | `completion_notification` ∈ `off` / `sound` / `toast` / `both`，默认 `both` | `SettingsRead` / `SettingsUpdate`，落在 `Setting` 表 | 提醒**用什么方式** |
| 逐任务 | `notify_on_complete`，默认 **`true`** | `DownloadOptions`，落在 `options_json` | 这个任务**要不要**提醒 |

**为什么逐任务开关的默认值要从 `false` 改成 `true`**：如果它出厂是关的，用户就必须
在每次提交前记得勾一下 —— 那等于把「设置里选了提醒方式」变成一句空话（选了却不响），
正是本目录要消灭的那类名实不符。改成默认开之后，设置里的选择才是唯一要管的地方。

**为什么不让设置项直接兼管「要不要」**（即 `off` 就是关、其余就是开）：
那样会丢掉逐任务粒度，而且「我明明选了弹窗，怎么没弹」会变成新的疑问。
现在两层的关系在两处都写明了：设置里那一项的说明里写着「要不要提醒由下载选项里的
『完成后通知』逐任务决定」；方式为 `off` 时那个开关显示成**不可勾**，并写明原因。

### 2. 提醒发生在浏览器里，后端只存偏好

提示音用 Web Audio **现场合成**一声「叮」（C6 1046.5 Hz → G6 1568 Hz，指数衰减），
没有一个音频文件要跟着仓库走 —— 也就没有版权、体积、路径三件事要操心。
浮层是普通 DOM，右下角，`position: fixed`。

播不播得出来必须**如实上报**三种结果，否则「用户说没听见」无从查起：
`played`（上下文在跑）/ `blocked`（浏览器还没放行音频）/ `unsupported`（环境没有 Web Audio）。
浏览器只允许用户手势之后出声，所以「加入下载队列」和设置里的「预览」都会先 `prime()`
一次 —— 前者是用户**必然**会点的一步，等于顺手把音频解锁了。

### 3. 触发条件是「状态跃迁」，不是「当前状态」

```ts
TERMINAL_JOB_STATUSES = new Set(["succeeded", "failed"]);
```

两条判据都不能少：

- **上一次的状态不是终态**：`jobs` 在每条 SSE 事件后整份重拉，不比对就会把「一进来就已经
  跑完」的历史任务反复播报一遍。
- **上一次见过这个任务**（`!== undefined`）：打开页面时就已经跑完的，用户没有「看着它跑完」
  这回事，播报等于把历史翻出来念一遍。

`cancelled` **不在**终态里：取消是用户自己点的。

### 4. 浮层在后台标签页不会自己消失

下载跑十几分钟是常态，用户多半切走了。这时开始倒计时，等于让提醒在他看不见的时候
自己消失 —— 浮层这种方式就白选了。所以后台只记「还剩多久」，`visibilitychange` 说
可见了才接着走。悬停同理会暂停缩回。

### 被否决的方案

| 方案 | 为什么不选 |
| --- | --- |
| 用浏览器 Notification API（系统通知） | 要权限申请，被拒后必须另写一套说明，且本机单用户工具里标签页通常就在眼前；权限被拒时的静默失败正是 H-01 点名的风险。本轮只做「不依赖权限」的两种方式。 |
| 后端发声 / 后端推 SSE 提醒事件 | 后端是本机服务，但它不知道浏览器有没有权限、页面是不是可见；让后端决定「该不该响」只会把判断搬到没有信息的地方。 |
| 撤掉那个开关 | 用户明确选择了「实现」这条路；而且提醒在长下载里是真需求。 |
| 只改前端，把勾过的任务 id 存 `localStorage` | 换个浏览器/清了缓存就丢，且跨设备不一致；读模型抬一个派生布尔值反而更简单。 |

## 未覆盖 / 如实说明      ← 必填

1. **没有在真实浏览器里听过那一声「叮」。** 合成参数（C6→G6、0.5 s、峰值增益 0.16）是
   按「不刺耳」选的，但好不好听只能人耳判断；测试只保证「排进了两个音、没有抛异常」。
   要调音色改 `frontend/src/notifications/notifications.ts` 的 `CHIME_NOTES` 即可，不影响其它逻辑。
2. **提示音能否出声取决于浏览器的自动播放策略。** 我在「加入下载队列」与「预览」里
   都调了 `prime()`，但**没有**在真实 Edge 上验证过「提交任务 → 十分钟之后切回来 → 声音
   是否真的响」。失败时会走 `blocked` 分支（不抛异常、也不显示任何东西）——
   也就是说**静默失败仍然是可能的**，只是不再无从查起。
3. **浮层没有做真实浏览器截图测量。** 右下角 20px 间距、360px 最大宽度、`z-index: 60`
   是按既有 `.modal-backdrop`（`z-index: 50`）推的，没有量过它会不会盖住任务中心
   右下角的按钮（`ai/ui/` 那套 CDP 探针本轮没跑）。
4. **只提醒 `succeeded` / `failed`，不提醒 `paused`。** `paused` 不是终态（还能重启），
   但如果用户手动暂停后忘了，它不会有任何后续提示。这是有意的选择，不是遗漏。
5. **老任务不会提醒。** 默认值改成 `true` 只影响**新提交**的任务：已经存进库里的
   `options_json` 里写着明确的 `false`，改默认值不会回溯它们。
6. **`completion_notification` 的非法值靠字符串白名单收敛**，没有做版本探测或迁移。
   落库值被外部改坏时退回 `both`，行为可预测但不会报警。

## 风险与回滚

- **契约新增两个字段**（`SettingsRead.completion_notification`、`JobRead.notify_on_complete`）。
  三处已同步（`schemas.py` / `types.ts` / `openapi.yaml`），`check_api_contract.py` 会拦漂移。
  老客户端不读新字段不会坏；老库里没有 `completion_notification` 这个 `Setting` 键时走默认值。
- **`notify_on_complete` 默认值 `false → true` 是行为变化**：不传该字段的 API 调用方
  （目前只有本项目前端）会从「不提醒」变成「提醒」。回滚只需把默认值改回去。
- **`Toggle` 组件多了一个 `disabled`**：其余 3 个调用点不传，默认 `false`，行为不变。
- 回滚方式：`git revert` 两个提交；数据面无迁移，`Setting` 表里多一行不影响其它功能。
