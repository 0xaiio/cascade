## 一句话结论

下载侧只认**中文和英文**两族字幕：先按视频的**主语言**（口语使用的语言，由 yt-dlp 的 `-orig`
ASR 轨给出，不是猜标题和频道）决定下载哪一族，人工字幕优先、没有才降级到 ASR，两族都没有就
**跳过字幕、不中断下载**；结论（语言 + 来源 + 文件路径）记在 `JobItem` 上。投稿侧在视频投稿
成功后把那份字幕文件转成 BCC 提交到 `oid=cid` 的 CC 字幕接口 —— 它是**字幕轨**而不是烧进画面的
硬字幕，观众可以自己关掉。字幕这一步失败**不影响稿件本身**，且有一条只重传字幕、绝不再投一次
视频的重试路径。

## 两处最容易写错、且错了不报错的地方

1. **B站 不认 `zh-CN` / `en-US`。** 需求里举的这两个值在平台侧是**非法语言**（`code=79011
   不合法的语言`），实测白名单只有 `zh` / `en` / `zh-Hant` / `zh-TW` / `zh-HK` / `ja` / `ko` /
   `yue` / `fr`。照着 `zh-CN` 实现的话，每一单都会在最后一步失败 —— 而且失败发生在视频**已经投
   出去之后**。详见 [02-design.md](02-design.md#语言标识与平台白名单)。
2. **「跳过字幕」不能用空语言列表表达。** yt-dlp 对空 `subtitleslangs` 的处理是「当没给」，
   然后按它自己的默认去挑英文 —— 把「跳过」悄悄变成「下载英文」。必须请求一个**匹配不到任何轨**
   的语言代码（族名 `zh` / `en` 正好如此，因为真实轨是 `zh-Hans` / `en-orig` 这种带后缀的），
   靠 yt-dlp 的 `fullmatch` 行为实现「一条都不下、也不报错」。
   详见 [02-design.md](02-design.md#为什么跳过要请求族名而不是给空列表)。

## 边界一句话

主语言判定依赖平台**提供** ASR 原声轨标记；平台不给时退化为「人工字幕里的中/英」，再退化为英文
（有界默认，不是随机猜）。字幕上传是**尽力而为**的附加步骤：字幕失败不算投稿失败，但也不静默
吞掉 —— 它有自己的三档状态（`posted` / `skipped` / `failed`）与一句给用户看的话。

## 三档状态的判据（2026-10-21 收紧，缺陷 [016](../../bug-fix/016-subtitle-lost-while-the-video-is-in-review.md)）

| 状态 | 只表示 |
| --- | --- |
| `posted` | 字幕已经在稿件上，观众可开关 |
| `skipped` | **确实没有可传的字幕**（没下载到 / 文件已删 / 格式不支持） |
| `failed` | 有字幕但这次没传上去 —— 包括**稿件还在审核、拿不到分P编号**这种「不是故障但也不是成功」的情形 |

前两档之外还有一个容易混的：稿件在审核（`state=-30`）时 `x/web-interface/view` 返回 `-404`，
`cid` 取不到，字幕无处可挂。这种情形**必须记 `failed`** —— 记 `skipped` 会让重试路径认为
「本来就没有字幕」，那条字幕就永久丢了（实测丢过两条）。判据一句话：
**一个枚举值不能同时表达「不需要」和「没做成」。**
