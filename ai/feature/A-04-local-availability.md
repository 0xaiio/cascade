# A-04　解析结果标注「本地已有」，重复下载前就知道会重下几条

来源：[`ai/plan/brainstorming.md`](../plan/brainstorming.md) §A-04。2026-11-11 落地，一项一个提交。

## 结论：判「已有」的代码早就写好了，缺的只是**在解析阶段跑一次**

`output_paths.discover_existing_output_path()` 与 `job_manager` 里 `skip_existing` 用的是同一套判据
（同一视频 id + 媒体后缀、排除 `.part`）。下载时它替我们省流量，但**用户看不见**：重复解析一个
200 条的合集，只有建完任务、跑起来才发现大部分被跳过。

所以这一条只做两件事：解析时算一次，界面上标出来。

## 目录规则必须与建任务时**同一套**

| 场景 | 目录 | 依据 |
| --- | --- | --- |
| 合集 | `<下载目录>/<合集标题清洗后>` | `api_support.job_download_dir()` |
| 单视频 | `<下载目录>` 根 | 同上 |

两者都是 `job_download_dir()` 的既有规则。解析时**还没有 job_id**，所以标题清洗成空目录名时
无法预知建任务会用哪个名字（那时会回落到 `playlist-<job_id>`）—— 这种情况一律不标：
宁可少提示，也不猜错目录。猜错的代价是「告诉你已有、其实没有」，比不提示更坏。

## 性能：一次枚举，不是每条一次

朴素做法是 `for entry in entries: discover_existing_output_path(entry.url, dir)`。
那个函数每次都把整个目录 `iterdir()` 一遍，于是复杂度是 **O(条目 × 文件数)**。

`discover_existing_media_by_id(ids, directory)` 改成一次 `iterdir()`：
从每个文件名里取出 `[id]` token（成品名是 `标题 [id].ext`），与想要的 id 求交。
同一 id 有多条时按文件名序取第一条（成品名稳定，顺序只为可复现）。

实测（NTFS，200 条 × 1000 个文件）：

| 写法 | 耗时 |
| --- | --- |
| 逐个 `discover_existing_output_path` | **1908.5 ms** |
| `discover_existing_media_by_id` | **16.7 ms**（114×） |

16.7 ms 落在一次解析的总耗时里可以忽略；1.9 秒不行 —— 那是每次解析都要付的。

## 接口与界面

- 契约：`VideoEntry.local: bool`、`AnalyzeResponse.local: bool`（单视频用；合集恒为 false）。
  两者都是**只读提示**，不改变任何行为。
- 条目表新增「本地」列：命中显示绿色「已有」徽标，其余是同列破折号；
  表上方汇总一句「本地已有 N 条：建任务时默认『跳过已下载』，这些条目不会重下（可在下载选项里关掉）」。
- 单视频：解析后若命中，单独一句「本地已有同名产物……」。
- 文案口径必须与机制一致：真正让它不重下的是 `skip_existing`（默认开），所以写「默认」并指出在哪儿关 ——
  只写「不会重下」会在用户关掉那个开关之后变成假话。

## 覆盖的边界

| 场景 | 结论 |
| --- | --- |
| 合集里部分条目已有 | 逐条标；汇总给出条数 |
| 一条都没有 | 不出现任何提示（不显示「本地已有 0 条」这种噪音） |
| 单视频已有 | 单独一句提示 |
| 只有 `.part` | **不算**已有（没下完） |
| 只有 `.jpg` / `.description` 等 sidecar | 不算（不是媒体） |
| 同一 id 有 `.mp4` 与 `.mkv` | 取文件名序第一条（可复现） |
| 下载目录不存在 | 全部按「没有」处理，不抛错 |
| 合集标题清洗成空 | 不标（目录名取决于未来的 job_id） |
| 旧后端（响应里没有 `local`） | 前端按「没有」渲染，不编提示 |

## 遗留

- 只判**成品媒体**：只下字幕（`subtitles_only`）或只缺字幕时，「已有」会显示为没有 —— 因为字幕不算成品。
  真要细分得给 `local` 一个枚举（视频 / 字幕 / 全有），本轮不做。
- 结果**不缓存**：每次解析都重新扫一遍目录。16.7 ms 不值得加缓存与失效策略。
- 只在解析时算：任务建好之后磁盘发生变化（比如手动删了文件），界面不会自己更新。
- 目录规则复制了 `job_download_dir()` 的「同名子目录」判断，没有抽公共函数 —— 两处都依赖
  `safe_path_name` 与同一条标题来源，抽出去要跨 `api_support` 与 `download` 两层；等第三处出现再抽。
