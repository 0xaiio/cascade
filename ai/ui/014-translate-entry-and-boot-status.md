# 014 · 「译为中文」文字按钮突兀，启动提示又被忽略

## 现象

两处观感问题，都是「功能对了，但用户看不出发生了什么」：

1. 任务中心的字幕按钮旁、B站 投稿预览表的字幕列里，各有一个写着「译为中文」的**文字按钮**。
   相邻的全是 36px 图标按钮，这四个文字按钮在尺寸、基线、视觉重量上都不一样，像临时贴上去的。
2. 首次点翻译时，抽屉里只有一行灰色小字「正在准备本机模型服务，首次启动约需十几秒…」。
   用户反馈「容易产生什么都没发生的误解」—— 它和下面「没有符合条件的条目」用的是同一个
   `.translation-hint` 样式，确实没有任何「正在做事」的视觉信号。

## 判据

- **入口**：四处（任务中心单视频 / 合集条目、投稿预览单视频 / 逐条预览）必须是同一个组件，
  不能只改一处；可访问名称保持 `译为中文 <标题>`，Tooltip 保持「把这条字幕译为中文」。
- **图标**：要同时表达「对字幕做事」和「目标语言是中文」。只有 CC 会和旁边的「打开字幕」
  撞脸；只有「中」字又丢掉操作对象。
- **状态**：等待不是普通提示，必须一眼看出「系统在做事、我不用做事」；
  但也不能伪装成进度条（此时一条都没译）。

## 修法

- 新组件 `TranslateToChineseIcon`：**lucide `Captions`（CC 字幕）+ 右下角 11px 蓝色「中」字角标**。
  CC 表示操作对象，角标表示目标语言，与相邻 CC 按钮区分开。图标 `aria-hidden`，
  可访问名称仍由按钮的 `aria-label` 承担。
- 四处入口统一换成该图标，尺寸 18 / 16 / 15px，按钮改用与相邻控件一致的 `icon-button`
  尺寸（36px）或表格内联 28px；`bili-inline-translate` 补上 Tooltip。
- 启动提示换成 `.translation-booting` 状态条：蓝底 `#f0f6ff`、4px 蓝色左边框、转圈图标、
  加粗标题「正在启动本机模型服务…」+ 副标题「首次约需十几秒，随后自动开始翻译，无需任何操作」，
  `role="status"` / `aria-live="polite"`。

## 验收

`tmp_acceptance/ui_translate_ux.py`（真实 Edge + CDP，**18 项全过**）：

- 图标按钮在「打开视频文件夹」右侧、同高、36px、按钮正文只有角标「中」、
  主图标是 `lucide-captions`、角标有实色底、Tooltip 未丢；
- 状态条 `role=status`、文案含「无需任何操作」、蓝底 `rgb(240,246,255)`、
  左边框 `4px`、标题 `font-weight>=700`、转圈动画 `animationName != none`。

截图：`tmp_acceptance/translate_ux.png` / `translate_ux_zoom.png`。
组件层另有 3 条断言钉住角标文本与状态条结构（jsdom 不量布局）。

## 一条通用判据

**「正在准备/正在初始化」不能复用普通提示的样式。** 它和「没有结果」在文案上只差几个字，
视觉上必须差一个量级：颜色块 + 动画 + 加粗，并明确告诉用户是否需要操作。
否则用户盯着 0/N 得出的结论就是「按钮没生效」。
