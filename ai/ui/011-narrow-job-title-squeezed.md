# 011 · 390px 下任务卡片的标题被挤成一列单字

## 问题

窄屏（390px）下，任务卡片头部是「复选框 + 标题 + 8 颗图标按钮」。按钮既不换行也不收缩，
把标题列压到**约 30px**：中文只能一个字一行，整张卡片被拉成近千像素高的窄条。
标题是用户识别任务的唯一线索 —— 这一档等于任务列表不可用。

实测（本机 headless Edge，390×844，`tmp_acceptance/probe_mobile_job_title.py`）：

| 指标 | 修复前 | 修复后 |
| --- | --- | --- |
| 标题列宽度 | **0 px**（被压到零） | **265 px** |
| 标题行数（Range 量的行盒数） | **36 行** | **2 行** |
| 操作区是否在标题下方 | 否（与标题重叠，`y` 相同） | 是 |
| 卡片高度 | 958 px | 152 px |

截图：[修复前](assets/011-before-mobile.png) / [修复后](assets/011-after-mobile.png)。

## 根因

`.job-row` 是 `display: flex`，但**没有 `flex-wrap`** —— 它永远只有一行，宽度不够就压缩子项。
而子项的收缩能力不对等：

```css
.job-main { min-width: 0; flex: 1; }   /* basis = 0%：可以一路缩到 0 */
.job-actions { display: flex; flex-wrap: wrap; gap: 8px; }  /* 按钮本身 36px，不可缩 */
```

`.job-main` 的 `flex: 1` 等价于 `flex: 1 1 0%`，它的基准宽度是 0、靠剩余空间撑开；
`min-width: 0` 又允许它被压到 0。8 颗 36px 按钮 + 7 个 8px 间距 ≈ 344px，
在 390px 视口的内容区（≈290px）里根本放不下 ⇒ 剩下的空间全被按钮占走，标题列归零。

`ai/ui/002`/`003` 的两条教训在这里也适用：**`min-width: 0` 只是把溢出换了个形式**，
真正要问的是「谁需要这条声明」—— 这里需要宽度的是标题，不是按钮。

## 修法

只在 `@media (max-width: 680px)` 里加三条（不动桌面版式）：

```css
.job-row     { flex-wrap: wrap; }        /* 允许换行 */
.job-main    { flex: 1 1 200px; }        /* **非零 basis**：先要 200px，不够才谈收缩 */
.job-actions { flex: 1 1 100%; justify-content: flex-end; }  /* 按钮自己占一整排 */
```

取「换行」而不是「把按钮收进更多菜单」：`ai/ui/007` 已经证明**动作藏起来等于没有**
（用户找不到重试入口）。换行只多占一行高度，代价是 60px。

## 覆盖

- **样式不变式**（`frontend/src/styles.test.ts`，+1 条）：`.job-row` 有 `flex-wrap: wrap`、
  `.job-main` 有**非零的 flex-basis**、`.job-actions` 占整排。jsdom 不做布局，
  这里钉的是**根因那条声明** —— 删掉它只有这条会红。
- **真实浏览器**（`tmp_acceptance/probe_mobile_job_title.py`，9 条断言全过）：
  390px 下量标题列宽度 / 行盒数 / 操作区位置；再**注入修复前的三条声明**复现缺陷，
  证明量到的差异确实来自它们（这一步是关键：否则「修好了」可能只是视口碰巧不对）。
  截图两张，见上表。

## 边界

- 只测了 390px（用户报告的那个宽度）。681–1023px 仍走桌面版式：8 颗按钮 + 标题在那个区间
  够用，未实测是否临界。
- 按钮在 390px 下会自己折成**两排**（290px 放不下 344px）。卡片高度从 92px 涨到 152px，
  换来标题可读 —— 这是有意的取舍。
