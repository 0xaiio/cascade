# 004 · 「重新体检」点下去没有任何可见效果

## 问题

设置面板的 B站 区右上角有个「重新体检」按钮。点它**屏幕上一个像素都不动**：
没有转圈、没有「已刷新」、结论也没变。用户据此判断「这个按钮没实现」。

## 原因

按钮**确实发了请求**，但它没有任何**可观察的副作用**：

- `refresh()` 只做一次 `setStatus(await getBiliStatus())`。体检结论在多数时刻是一样的
  （工具在、登录文件在），于是 React 的 diff 结果为空 —— DOM 完全不变；
- 按钮没有 loading 态：`{checking}` 这个概念当时不存在，点下去连文案都不变；
- 也没有落款时间：两次点击在界面上**完全不可区分**；
- 更没有超时：`GET /api/bilibili/status?probe_account=true` 会真的往 B站 发请求，
  本机直连 `member.bilibili.com` 时域名解析能卡 40 秒以上（`socket` 超时管不到 DNS）。
  那段时间里按钮同样是死的。

**可量化的判别**：在浏览器里记录点击前后的 `.bili-login-section` 的 `outerHTML` 与按钮的
`disabled`/`textContent` —— 旧实现三者全等。这就是「无任何效果」的准确含义：
不是没跑，而是**跑了也看不出来**。

## 修复方案

三件**可观察**的东西，都在真实浏览器里验过：

1. **加载态**：点下去立刻变成「体检中…」并 `disabled`，结束后回到「重新体检」。
2. **落款**：「上次体检 11:58:03」写在按钮左边，等宽数字（秒数跳动时不会左右晃）。
   结论不变时，这是唯一能证明「这一下真的跑了」的东西。
3. **超时兜底**：账号探测 12 秒没回来就退回**离线**体检（`probe_account=false`，
   不发网络请求），并在下面写一句「账号探测 12 秒还没回来……下面是离线结论」。
   判据挪进纯模块 `biliHealth.runHealthCheck()`，界面只负责显示文案 ——
   于是超时/降级/网络错误三条分支可以用 20ms 的时限单测，不必在界面测试里摆弄假定时器。

为什么不是「点一下弹个 toast」：那只是把「我看不出来」换成「我知道它跑了」，但**结论新旧**仍然不可知；
落款同时解决了两件事（跑了 / 什么时候跑的）。

## 效果

真实浏览器（`tmp_acceptance/probe_recheck_button.py`，11 条断言全过）：

```
点之前   text=重新体检  disabled=False  stamp=上次体检 12:20:14
点一下   text=体检中…   disabled=True   stamp=上次体检 12:20:14
结束后   text=重新体检  disabled=False  stamp=上次体检 12:20:17   ← 换了
```

## 验证

| 用例 | 钉住什么 |
| --- | --- |
| `重新体检真的会再查一次，并留下体检时间` | 点击后再发一次 `probe_account=true`，且页面出现 `上次体检 HH:MM:SS` |
| `体检进行中按钮不可点，并写明「体检中…」` | 加载态存在（用稳定句柄 + `waitFor`，不按名字抓瞬时元素） |
| `biliHealth.test.ts`（5 例） | 按时返回就用它的结论；超时退回离线并标 `timedOut`；网络错误照旧抛；离线也失败时抛；兜底时限是 12 秒 |
| 探针 11 条 | 真实布局下的三种状态与落款刷新 |

## 风险与回滚

- 多了一次「落款」文案，不影响任何逻辑；`checking` 与 `busy` 分开，体检时仍可扫码/导入。
- 12 秒兜底只在超时时多打一次**离线**接口（不发网络），代价可忽略。
- 回滚：`git revert <commit>`。

## 未覆盖 / 如实说明

- 12 秒超时路径在**真实浏览器**里没有稳定复现（本机后端通常 0.7~3 秒返回，
  偶发 >20 秒的那几次是探针自己在卡，不是这条分支）；它只有单测（20ms 时限）覆盖。
- 落款时间用的是浏览器本地 `toLocaleTimeString("zh-CN", {hour12:false})`，跨时区/跨语言环境下
  格式可能不同；用例只断言前缀与长度。
